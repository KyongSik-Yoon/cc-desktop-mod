# cc-desktop-mod: Claude Code 터미널을 데스크톱 앱처럼

[English](README.md) | **한국어**

**desk-look** 은 Claude Code CLI 터미널 UI 를 Claude 데스크톱 앱 Code 탭처럼 보이고 동작하게 만드는 Claude Code 플러그인(mod)입니다.
Claude Code 의 함수 훅 플러그인이라, 엔진은 그대로 두고 화면에 그리는 방식만 바꿉니다. 데스크톱 앱 Code 탭(`desktop` 화면)에서는 아무것도 바꾸지 않습니다.

<img src="docs/demo.gif" alt="동작 중인 desk-look: Claude 가 일하는 동안의 진행 띠, 한 줄로 접힌 도구 호출, 고친 파일 카드, 턴이 끝나면 저절로 열리는 마크다운 미리보기, 다음 프롬프트와 함께 가는 diff 줄 댓글, 컨텍스트 패널" width="1280">

**한눈에 보기**

- **데스크톱 앱처럼 읽히는 대화 기록**: 프롬프트 말풍선, 폭을 채우는 표·mermaid 그림·알림 상자가 든 데스크톱 스타일 마크다운, 한 줄로 접혀 눌러서 펴는 도구 호출, 서브에이전트마다 카드, 계획 카드, 질문 카드, 턴마다 고친 파일 카드
- **입력창 위 상태 띠**: 저장소·브랜치·`+N −M`, 그리고 PR 체크·컨텍스트 사용량·도는 백그라운드 작업 칩(desk-slack 이 있으면 안 읽은 Slack 메시지 칩도)과 지금 단계와 지금 도는 일을 보여 주는 진행 띠
- **오른쪽 패널 일곱 개**, 명령이나 칩을 눌러 엶: diff(`/desk-diff`), 이번 턴에 돈 일(`/desk-activity`), 백그라운드 작업(`/desk-tasks`), PR(`/desk-pr`), 마크다운 미리보기(`/desk-preview`), 컨텍스트·사용 한도(`/desk-context`), 최근 세션(`/desk-sessions`)
- **diff 줄 댓글**: `/desk-diff` 에서 줄 번호를 눌러 줄·범위에 댓글을 달면, 다음 프롬프트와 함께 Claude 에게 감
- **마크다운 미리보기**: Claude 가 한 턴에 쓴 문서는 턴이 끝나면 미리보기 패널에 저절로 열림
- **GitHub 와 GitLab**: PR 은 `gh`, MR 은 `glab` 으로 읽음
- **Asana·Slack 패널**은 같은 마켓의 플러그인 두 개 [desk-asana](desk-asana/README.ko.md)·[desk-slack](desk-slack/README.ko.md) 로: 쓰는 것만 설치하면 되고, desk-look 자신은 스스로 네트워크 요청을 하지 않고 MCP 서버도 부르지 않음
- **영어·한국어** 표시, 기본은 Claude Code 언어 설정을 따름

## 명령

- `/desk-diff [파일|branch|commits]`: diff 패널: 커밋 안 한 변경, 브랜치 전체, 커밋별
- `/desk-activity`: 이번 턴에 돈 일: 시간 막대와 Claude 의 설명 글·호출 흐름
- `/desk-tasks [번호]`: 백그라운드 작업 패널: 에이전트, 백그라운드 셸, 모니터
- `/desk-pr`: 지금 브랜치의 PR·MR, 머지 버튼
- `/desk-preview [파일]`: 마크다운 미리보기 패널: 문서를 대화와 같은 모양으로
- `/desk-context`: 컨텍스트 내역, 실린 것, 이 세션의 흐름, 캐시, 비용, 사용 한도
- `/desk-sessions [번호]`: 프로젝트별 최근 세션과 검색, 세션 이동
- `/desk-fold`: 열린 패널을 접어 대화를 넓게, 다시 치면 같은 스크롤 위치로 편다
- `/desk-quote`: 대화 기록에서 마우스로 고른 글을 `>` 인용으로 입력창에 넣어 묻기. 쓰던 글이 있으면 인용은 그 위(앞서 넣은 인용 다음)에 들어가고 커서는 쓰던 자리에 남음. 입력창의 `>` 줄(치거나 붙여넣거나 넣은 것)은 인용처럼 표시는 흐리게, 글은 기울여 흐린 색으로
- `/desk-update`: desk-look 과 설치한 desk-asana·desk-slack 을 최신 버전으로

패널 명령은 Claude 가 일하는 중에도 바로 실행된다. 큐에 들어가거나 턴을 멈추지 않고 패널만 연다.

## 대화 기록

![Claude Code 터미널의 desk-look: 프롬프트 말풍선, 접힌 도구 호출, 마크다운 표, mermaid 순서도, Note 상자, 고친 파일 카드](docs/screenshot.png)

각 항목은 터미널 기본 → desk-look 순서입니다.

- **내 프롬프트**: `>` 로 시작하는 줄 → 회색 말풍선 (한 줄은 알약, 여러 줄은 모서리만 둥근 상자). 위치는 왼쪽(기본)·오른쪽. 붙여 넣은 이미지는 말풍선 위 썸네일로, 긴 붙여넣기 글은 누르면 펼치는 `❐ 붙여넣은 글 · N줄` 한 줄 칩으로
- **답변**: `●` 불릿 + 엔진 마크다운 → 데스크톱 산문 스타일 마크다운 렌더러
- **표**: 격자 표 → 폭을 채우는 표, 헤더 회색 바탕, 행 구분선
- **mermaid**: 코드 블록 → 박스 그림 ([lovely-mermaid](https://github.com/xl0/lovely-mermaid)), 화살촉이 상자에 꽂힘
- **`> [!NOTE]` 알림**: 인용문 → 종류별 색 테두리 박스
- **코드 블록**: 복사 수단 없음 → 마우스를 올리면 위 테두리 오른쪽에 `⧉ copy`, 누르면 `/copy` 와 같은 길로 복사
- **도구 호출**: 호출마다 행 + 결과 블록 → 이어진 호출을 `Ran 2 commands, edited a file +3 −1 ›` 한 줄로 접고, 누르면 펼침. 펼치면 편집 diff 가 바로 보임(파일 기준 줄 번호, 앞뒤 세 줄 문맥). 터미널 테마를 알면 데스크톱 diff 모양. ctrl+o 화면은 엔진의 전체 행 그대로
- **서브에이전트**: `Ran an agent` 한 줄, 알림·메시지는 ctrl+o 로만 펼침 → 에이전트마다 카드(종류·설명, 도구 수·토큰·시간·바꾼 줄, 눌러서 결과). 백그라운드 알림은 `✓ 설명 completed · 5s`, 에이전트 메시지는 `◆ 이름 첫 줄 ›` 을 눌러 그 자리에서 펼침. 턴이 백그라운드 에이전트를 기다리며 끝나면 `Waiting for N background agents to finish` 아래에 에이전트마다 `··· 종류 설명 ›`(끝나면 상태), 누르면 `/desk-tasks` 의 그 에이전트
- **계획 (ExitPlanMode)**: 다른 도구와 한 줄로 접힘 → 따로 카드 `◇ Plan 승인됨`(대기·거절·중단도 표시), 계획을 마크다운으로. 길면 앞부분만 보이고 `Show all` 로 펼침. 승인 창은 엔진 것 그대로
- **질문 (AskUserQuestion)**: 입력창 아래 목록 → 입력창 바로 위 질문 카드. 입력창이 비어 있으면 숫자만 눌러 고르기(`1`-`8` 선택지, `0` 제출, `9` 기본 창), 여러 개 고르기 ☐/☑, `Other` 는 두 번 클릭해서 입력(첫 클릭은 띠 선택, 입력칸은 네 줄까지 자람), 선택지 미리보기는 마우스를 올리면. 카드가 뜨면 엔진 창처럼 알림(`preferredNotifChannel`). 기록에는 `Asked 질문 → 답`
- **턴 끝**: 소요 시간 줄 → 그 턴에 고친 파일 카드 `Edited N files +N −M`(파일 줄을 누르면 `/desk-diff` 패널이 그 파일에서 열림), 오른쪽 끝에 답변 복사 `⧉ copy`, 그 옆 `❝ quote` 는 그 답을(답 안에서 고른 글이 있으면 그 부분만) 인용으로 입력창에
- **명령 출력**: 평문 → 표·제목·코드·인용이 든 출력은 답변처럼 마크다운으로

## 입력창 주변

각 항목은 터미널 기본 → desk-look 순서입니다.

- **아래턱 띠**: 데스크톱 입력창 아래턱 같은 둥근 회색 띠: 왼쪽 `저장소  브랜치`, 오른쪽 `+N −M`(누르면 `/desk-diff` 패널), 다음 프롬프트에 같이 갈 diff 줄 댓글이 있으면 `✎ N`
- **PR 칩**: 지금 브랜치의 PR: `#12 ✓ 5/5`, 실패 `✗ 1`, 진행 중 `● 3/5`, 안 풀린 리뷰 `◆ 2`. GitLab MR 은 `!7` 로, 파이프라인 job 과 안 풀린 토론을 셈. 누르면 `/desk-pr` 패널
- **컨텍스트 칩**: 컨텍스트가 반을 넘기면 `◑ 62%`(75% 부터 주의색, 90% 부터 경고색). 누르면 `/desk-context` 패널
- **작업 칩**: `1 shell still running` → 백그라운드 작업이 도는 동안 `⋯ 2`. 누르면 `/desk-tasks` 패널
- **진행 띠**: 기다리는 동안 보이는 것 없음 → 턴이 도는 동안 입력창 위 두 줄. 윗줄은 지금 단계: `TodoWrite`·`TaskCreate` 의 할 일 목록(`✓ 2  ◉ 검증 중 8m 2s  ○ 정리 +1   2/5`), 그 도구가 없는 세션(Claude 5 모델은 Claude Code 가 뺌)이면 Claude 가 마지막 도구 호출 앞에 쓴 글의 첫 문장(`✓ 2  ◉ 이제 .12 에서 돌릴게요.   단계 3`). 아랫줄은 지금 도는 일: 도구 호출과 그 시간, 셸 명령이면 띄운 프로그램과 CPU(`▶ 커서 재조회 검증 · 8m 2s · java 97%`, 리눅스), Claude 가 글을 쓰는 동안은 `응답 중`. 그 프로그램이 3분 동안 CPU 도 입출력도 쓰지 않으면 `! 변화 없음 3m 10s`(`ssh` 같은 네트워크 명령은 원격이 일하는 중일 수 있어 흐리게). 아랫줄을 누르면 `/desk-activity`. 아랫줄은 10초가 지나거나 윗줄에 단계가 생기면 바로 생기고, 턴이 끝나면 아랫줄은 접히고 윗줄은 마지막 단계를 끝난 것으로 30초 남김(`bandAfterTurn`, ✕ 로 닫기). 긴 턴은 턴 끝 줄 아래에 흐린 `명령 3 (실패 1) · 에이전트 2 · 할 일 5/5` 를 남김
- **진행 표시**: `✻ Simmering… (12s · ↓ 300 tokens)` → `●·· Running…  2m 29s · high` (하는 일에 맞춘 낱말, 클레이색 점, 지금 서 있는 effort. 작업 중에 바꾼 수준은 모델이 받는 다음 메시지부터)
- **모드 표시**: 입력창 오른쪽 아래 흐린 글자 → 알약 모양 칩 (omarchy 테마일 때)
- **힌트 줄**: `? for shortcuts` → 질문 카드가 떠 있으면 끝에 답하는 키(`숫자로 고르기 · 9 기본 창 · Esc 취소`)

## 오른쪽 패널

패널은 터미널 오른쪽, 대화 기록 옆에 열립니다.

### `/desk-diff [파일]`: diff

![브랜치 범위의 /desk-diff 패널: 접고 편 파일, 구문·단어 강조](docs/diff.png)

데스크톱 diff 패널처럼 파일별 diff 를 범위 세 가지로:

- `커밋 안 한 변경`, `브랜치 전체`(기본 브랜치에서 갈라진 뒤 전부, `merge-base` 기준), `커밋별`(커밋을 누르면 그 커밋 diff)
- 파일 이름(뒷부분만 써도 됨)을 주면 그 파일로 스크롤, `branch`·`commits` 를 주면 그 범위로 열림
- 패널은 파일이 접힌 목록으로 열림. 파일 머리 줄을 누르면 그 파일 diff 를 펴고 그리로 스크롤하며, 펴 있던 파일은 접혀 한 번에 하나만 펴짐. 다시 누르면 접힘. `z` 는 모두 펴기·접기로, 변경 전체를 한 번에 훑을 때 씀(`커밋별` 에서는 커밋과 그 파일 전체, 커밋 여러 개를 함께 펼쳐 둘 수 있음)
- `r` 은 diff 다시 읽기
- `n`·`p` 는 다음·이전 파일: 하나만 펴 보는 중이면 그 파일을 펴고(보던 파일은 접힘), `z` 로 여럿 펴 두었으면 그 머리 띠로 스크롤
- `f` 는 목록 위에 파일 거르기 칸을 엶: 경로 일부를 치면(띄어 쓰면 모두 맞는 것) 맞는 파일만 남고, Enter 는 첫 파일을 폄. `✕` 는 지우고 닫음
- `브랜치 전체`·`커밋별` 에서 `vs <기준> ⌄`(`v`) 를 누르면 최근 커밋 순 로컬·원격 브랜치에서 기준을 고름. `자동` 은 찾아 둔 기준(PR 의 base, origin 의 기본 브랜치, main·master·develop 순)으로 돌아감
- `안 바뀐 줄 N개` 를 누르면 그 줄들을 그 자리에 폄. 지금 파일에서 읽음(`커밋별` 은 그 커밋의 파일에서)
- 커밋 안 한 파일에는 `되돌리기`: 5초 안에 두 번 눌러야 `git restore`(새 파일은 없음)
- 터미널 테마(Omarchy)를 알면 데스크톱 diff 패널처럼 그림: 파일마다 머리 띠, 줄 전체 폭 초록·빨강과 왼쪽 색 줄, 번호 한 칸, 삭제 줄에도 문법 색, 바뀐 단어는 더 진하게, 안 바뀐 구간은 `안 바뀐 줄 N개`. 보이는 부분 앞뒤만 그려서 수천 줄 diff 도 짧은 diff 처럼 스크롤됨. git 밖에서 이 세션에 고친 파일은 `이 세션에서 고친 git 밖 파일` 묶음 아래(누르면 묶음을 접음) 편집마다 따로, 사이에 `· 다음 편집`. 테마를 모르면 지금처럼 엔진 diff
- 데스크톱 diff 패널처럼 줄에 댓글: 줄 번호를 누르면 그 줄 아래에 입력칸이 열리고, 같은 파일의 다른 줄 번호를 누르면 범위가 됨. 댓글은 여러 줄로 쓸 수 있음(줄바꿈은 입력창에서처럼). Enter 로 담은 댓글은 그 줄 아래(`✕` 로 지움)와 아래턱의 `✎ N` 칩에 남았다가, 다음 프롬프트를 보낼 때 Claude 가 읽는 context(파일·줄, 그 줄들, 댓글)로 같이 가고 비워짐. 슬래시 명령에는 붙지 않음. 위 그림처럼 테마를 알 때만

### `/desk-activity`: 이번 턴에 돈 일

`/desk-activity` 나 진행 띠의 아랫줄을 눌러 엶. 지금 턴을, 턴이 끝나면 지난 턴을 보여 줌(백그라운드 작업 끝남 알림에만 답한 턴은 그 앞 턴을 남김):

- **시간 막대**: 메인 대화 하나, 이 턴이 띄운 에이전트마다 하나, 백그라운드 셸 하나. 턴 동안(그리고 턴이 띄운 일이 끝날 때까지): `░` 탐색, `▓` 편집, `▒` 테스트(짧은 사건, 긴 명령 위에 그림), `━` 명령·위임(색으로 구분), `─` Claude 응답 중
- **흐름**: Claude 의 설명 글(`◉`, 호출 앞 글의 첫 문장)과 호출을 차례로, 턴 시작부터의 시각과 함께. 읽기·찾기는 한 줄로 묶고(`Read 6 · Grep 3`), 편집은 파일마다 `+N −M`, 명령·테스트는 `✓`·`✗`·`▶`(도는 중)와 시간
- **에이전트**·**백그라운드**: 이 턴이 띄운 것의 상태·도구 수·시간. 도는 백그라운드 셸은 출력 마지막 줄. 누르면 `/desk-tasks` 의 그 작업

### `/desk-tasks [번호]`: 백그라운드 작업

![/desk-tasks 패널: 도는 에이전트(가져오는 중)·모니터·백그라운드 셸과 Done 아래의 끝난 셸](docs/tasks.png)

데스크톱의 Background tasks 처럼, 이 세션의 에이전트, 백그라운드 셸(`run_in_background`, Ctrl+B, 시간 초과로 넘어간 명령), 모니터를 `실행 중`·`끝남`으로 나눠 보여 줍니다.

- **에이전트**: 모델, 토큰, 도구 수, 지금 하는 일(`페이지 받는 중`). `대화 보기` 는 받은 지시, 답변, 대화 기록처럼 접힌 도구 호출, 최종 보고. `메인 화면에서 보기` 는 그 에이전트의 대화 전체를 메인 화면에 띄우고, 그때 입력한 프롬프트는 그 에이전트에게 갑니다. 보고 있는 에이전트 카드에는 `◉ 보는 중`, `‹ 메인 대화로` 로 돌아옴
- **셸·모니터**: 명령. `자세히` 는 상태, 실행 시간, 결과 한 줄, 끝난 뒤 출력 끝부분
- 도는 작업의 `■ 멈춤` 은 5초 안에 한 번 더 누르면 멈춤
- `z` 로 `끝남` 을 접고, `c` 로 끝난 작업을 목록에서 모두 지우고, `지우기` 로 한 장씩 지움
- 카드를 누르거나 번호를 주면 상세. 위와 맨 아래의 `‹ 목록`(`b`) 으로 목록에 돌아옴

### `/desk-pr`: PR

지금 브랜치의 PR(GitHub, `gh`)이나 MR(GitLab, `glab`):

- 상태, `base ← head`, `+N −M`, 리뷰 결정과 병합 상태
- 실패·진행 중 체크(통과는 접어 둠), 안 풀린 리뷰
- 실패한 체크나 리뷰 옆 `Claude에게 맡기기` 를 누르면 그 내용을 입력창에 채움
- `머지` 는 5초 안에 두 번 눌러야 머지하고, 패널이 본 head 커밋일 때만 합니다(그 사이 푸시되면 머지가 거절됨). 체크가 아직 돌면 `파이프라인 성공하면 머지`(GitLab)·`체크 통과하면 머지`(GitHub)로 바뀌어 자동 머지를 겁니다. 열려 있고 Draft 가 아니며 실패한 체크가 없고 호스트가 머지 가능하다고 할 때만 보입니다. 머지 방식은 저장소 설정을 따릅니다: GitLab 은 MR 의 squash 설정, GitHub 은 허용된 것 중 merge → squash → rebase 순. 원격 소스 브랜치는 지우고(GitHub 자동 머지는 저장소가 head 브랜치를 지우게 해 둔 경우만), 로컬 브랜치는 건드리지 않음
- `r` 은 PR 다시 읽기
- 그 밖에는 바꾸지 않음: 승인·댓글·`Ready for review` 없음

### `/desk-preview [파일]`: 마크다운 미리보기

### `/desk-context`: 컨텍스트와 사용량

<img src="docs/context.png" alt="/desk-context 패널: 항목 색 컨텍스트 막대, 항목별 막대, 컨텍스트에 실린 것, 압축 표시가 있는 이 세션 그래프, 캐시, 비용, 사용 한도" width="540">

`/context` 격자 대신:

- 컨텍스트 막대: 항목마다 제 색, 남은 자리는 가는 선, 자동 압축 여유분은 점선(토큰 / 창, 자동 압축 지점)
- 항목별 내역, `/context` 와 같은 분류에 막대를 붙여서(로컬 추정이라 API 요청 없음)
- 컨텍스트에 실린 것, 묶음마다 접혀 있다가 누르면 펼침: 서버별 MCP 도구(필요할 때 싣는 수), 메모리 파일, 스킬 목록(세션의 스킬 중 몇 개가 목록에 드는지), 커스텀 에이전트, 각각 토큰
- 이 세션: 턴이 끝날 때마다 컨텍스트가 찬 정도를 그래프로. 세로축은 가장 높은 점에 맞추고, 자동 압축 높이는 `┈`, 대화를 압축한 자리는 `▲`. 컨텍스트 칩이 턴마다 이미 읽은 값을 적을 뿐 따로 묻지 않는다. 플러그인을 다시 올리거나 창이 다른 세션으로 넘어가면 처음부터 쌓고, 제목에 언제부터인지 단다
- 캐시: 지난 턴의 입력이 캐시에서 읽음·캐시에 씀·새로 들어감으로 나뉜 몫, 그래프의 턴들 동안 캐시에서 읽은 몫
- 비용: 세션 비용, 턴마다 막대, 지난 턴 비용
- 5시간·7일 사용 한도와 초기화까지 남은 시간
- 항목별 내역과 실린 것은 패널을 열 때와 `↻`(`r`) 때 계산한다. 이 세션 그래프·캐시·비용·한도는 턴 끝에 이미 읽은 값으로 턴마다 바뀌므로, 열린 패널도 턴마다 계산을 더하지 않고 닫힌 패널은 아무 일도 하지 않는다

### `/desk-sessions [번호]`: 최근 세션

최근 세션을 프로젝트별로, 맨 위 검색칸(제목·폴더, Enter 로 첫 결과)과 함께. 처음엔 지금 폴더 묶음만 펴져 있습니다. 묶음 머리를 누르면 접고 펴고, `z` 는 모두 접기·모두 펴기, 검색 중에는 모두 펴서 보입니다. `f` 는 검색칸으로, `r` 은 새로 읽기. 지금 떠 있는 세션은 줄 끝에 칩이 붙습니다(`claude agents --json` 에서 읽음): 백그라운드 세션은 `백그라운드`(쉬는 중)·`작업 중`·`응답 대기`, 다른 터미널에서 열린 세션은 `다른 창`.

줄을 누르거나 번호를 주면:

- **같은 폴더의 세션**: 지금 창에서 바로 그 세션으로 넘어갑니다(`/resume <id>` 실행). 실행이 막히면 입력창에 채워 두니 Enter 를 누르면 됩니다.
- **다른 폴더의 세션**: 지금 창이 그 폴더로 옮겨 가(`/cd`) 그 세션으로 넘어갑니다. 명령 실행이 막히면 `cd <폴더> && claude --resume <id>` 를 클립보드에 복사합니다(`wl-copy`).
- **떠 있는 백그라운드 세션**: `claude stop <id>` 로 멈추고(대화는 남음) 위와 같이 넘어갑니다. 작업 중이면 하던 턴이 끊기므로 한 번 더 눌러야 합니다.
- **다른 터미널에서 열린 세션**: [herdr](https://herdr.dev) 안이면 그 세션이 열린 herdr 탭으로 옮겨 갑니다. 그 밖에서는 안내만 하니 그 창에서 이어 가세요.

## 설치

desk-look 은 Claude Code 최신 버전에 맞춰 만들고 그 버전에서만 확인합니다. Claude Code 를 최신으로 유지하세요. 옛 버전에서는 엔진이 아직 그리지 못하는 부분이 엔진 기본 모양으로 나옵니다.

Claude Code 터미널 세션의 프롬프트에서:

```
/plugin install desk-look --marketplace KyongSik-Yoon/cc-desktop-mod
```

마켓플레이스 추가를 물으면 `y`, 범위는 user 를 고르면 됩니다.

Asana·Slack 패널은 같은 마켓에서 쓰는 플러그인을 더 설치합니다:

```
/plugin install desk-asana@cc-desktop-mod
/plugin install desk-slack@cc-desktop-mod
```

## 설정

`/config` 에서 `desk-look` 으로 찾으면 아래 항목이 나옵니다.

- `language`: `auto` (기본), `en`, `ko`. desk-look 이 그리는 글(패널·버튼·알림·입력창에 채우는 글)의 언어. `auto` 는 세션이 시작될 때 Claude Code `/config` 의 `language` 를 따름: 한국어(Korean)면 한국어, 그 밖에는 영어. 언어 설정 없이 한국어로 쓰려면 `ko`
- `bubbleSide`: `left` (기본), `right`. 내 프롬프트 말풍선 위치. 엔진이 말풍선 아래에 그리는 첨부 줄(`└ 1 skill available` 등)은 플러그인이 옮기지 못해 늘 왼쪽이라, 왼쪽이면 나란해집니다. `right` 는 데스크톱 앱처럼
- `askNotify`: `on` (기본), `off`. 질문 카드가 뜰 때 알림. 엔진 창은 뜰 때 알림을 보내지만 카드가 뜬 동안엔 엔진이 보내지 않아서 카드가 직접 보냅니다
- `prBar`: `on` (기본), `off`. 입력창 띠 옆 PR 칩. 세션을 시작할 때와 턴이 끝날 때 지금 브랜치의 PR 을 `gh`(GitHub)·`glab`(GitLab)으로 읽음(30초에 한 번까지). 열린 PR 의 체크(GitLab 은 파이프라인 job)가 도는 동안은 턴과 상관없이 15초마다 다시 읽고, 체크 상태가 그대로면 간격을 두 배씩 늘려 2분마다까지(runner 를 기다리는 job 처럼 끝나지 않는 체크가 계속 묻지 않게). 둘 다 없거나 어느 쪽 저장소도 아니면 숨기고 그 브랜치에서는 다시 묻지 않음(네트워크 오류는 다음 턴에 다시 읽음). `/desk-pr` 패널은 설정과 상관없이 열 수 있음
- `previewAutoOpen`: `on` (기본), `off`. Claude 가 쓴 마크다운 문서를 턴이 끝날 때 미리보기 패널에 엶. `off` 면 `◫` 칩과 `/desk-preview` 로만
- `replyInBlocks`: `on` (기본), `off`. Claude 의 답을 0.1초마다 몇 줄씩 흘리지 않고 블록째 보여 줌: 도구 호출 앞 글은 그 호출과 함께, 턴 끝 답은 통째로 나옴. 기다리는 동안 스피너에 모은 줄 수. 화면보다 긴 블록도 통째로 나와서 화면이 그 끝에 가 있으니 앞부분은 올려서 읽음. Esc 로 끊어도 모은 글은 보임. 모으기는 답 스트림 자체를 늦춰 Remote Control(Claude 앱, claude.ai/code)도 덩어리로 받으므로, 마지막 프롬프트를 앱에서 보냈으면 앱의 부드러운 흐름을 지키려고 평소처럼 흘림
- `contextChip`: `auto` (기본), `always`, `off`. 입력창 띠 옆 컨텍스트 칩. `auto` 는 50% 이상일 때만(상태 줄이나 다른 플러그인이 이미 늘 보여 주는 경우가 많아서), `always` 는 늘, `off` 는 끔. `/desk-context` 패널은 설정과 상관없이 열 수 있음
- `bandAfterTurn`: `off`, `10`, `30` (기본), `60`, `keep`. 턴이 끝난 뒤 입력창 위 진행 띠를 마지막 단계까지 끝난 것으로 남겨 두는 초. 끝의 ✕ 로 먼저 닫을 수 있음. `off` 는 턴이 끝나면 바로 접고, `keep` 은 닫거나 다음 턴이 시작될 때까지 남김

## 업데이트

입력창에서 `/desk-update`, 또는 셸에서:

```bash
claude plugin update desk-look
```

`/desk-update` 는 설치한 desk-asana·desk-slack 도 함께 올리고, 새 버전을 받았으면 `/reload-plugins` 까지 대신 실행합니다. 셸 명령으로 올렸으면 세션에서 `/reload-plugins` 를 실행합니다.

## 환경별 동작

- **색**: 엔진 테마 키(`text`, `inactive`, `claude` …)를 써서 밝은·어두운 테마를 모두 따라갑니다.
- **말풍선 회색 면**: [omarchy](https://omarchy.org) 테마(`~/.local/state/omarchy/current/theme/colors.toml`)를 읽을 수 있을 때만 그립니다. 테마를 바꾸면 3초 안에 따라갑니다. 그 밖의 환경에서는 둥근 테두리 말풍선입니다. 둥근 끝은 Nerd Font 반원 글리프와 Symbols for Legacy Computing 블록을 씁니다. 그림을 그릴 수 있는 터미널(아래)에서는 여러 줄 말풍선의 모서리를 작은 그림으로 그려 제대로 둥글게 나옵니다. 입력창 아래턱 띠도 같아서, 테마를 못 읽으면 회색 띠 없이 칩만 그립니다. `/desk-*` 패널도 같은 회색을 바탕으로 깝니다. 256색으로 그리는 tmux 안에서는 256색 팔레트의 가장 가까운 회색을 써서, 어두운 테마의 말풍선이 밝아지지 않습니다.
- **이미지 썸네일과 둥근 말풍선 모서리**: kitty·Ghostty 와 전체 화면 그리기의 iTerm2 3.5 이상에서 그리고(iTerm2 에서는 2 MiB 가 넘는 붙여 넣은 그림은 `[Image #N]` 글자로 둡니다). tmux 3.3 이상 안에서는 Claude Code 처럼 그 터미널(kitty 는 0.28 이상)에서 tmux 를 붙이고 `tmux set -g allow-passthrough on` 과 `tmux set -g focus-events on` 을 켰을 때 그립니다(여기서도 2 MiB 가 넘는 붙여 넣은 그림은 글자로 둡니다). zellij 안에서는 그리지 않습니다. herdr 안에서는 herdr `config.toml` 의 `[experimental]` 에 `kitty_graphics = true` 와 Claude Code 의 `CLAUDE_CODE_FORCE_TERMINAL_IMAGES=1` 이 모두 있어야 합니다. 없으면 Claude Code 가 터미널 이름을 물었을 때 herdr 가 대답해 그림을 그리지 않습니다.
- **질문 카드**: 터미널 하나만 붙은 세션에서만 씁니다. Remote Control 이 켜져 있으면 마지막 입력이 터미널에서 왔을 때만 카드를 띄우고, 1분 동안 아무도 건드리지 않으면 엔진의 기본 질문 창으로 넘겨 모바일·웹 앱에서도 답할 수 있게 합니다. 마지막 입력이 앱에서 왔으면 처음부터 기본 창이 뜹니다. Esc 는 턴을 멈추므로 질문도 취소됩니다.
- **256색 터미널의 diff 색**: 섞어 만든 줄·단어 틴트는 `COLORTERM` 이 `truecolor`·`24bit` 이고 tmux 밖일 때만 씁니다. 그 밖에서는(tmux 안에서는 엔진이 색을 256색으로 줄입니다) xterm 256색 팔레트에 있는 색을 써서, 바뀐 단어가 줄 바탕과 구분되게 합니다.
- **링크**: 백틱 안의 URL 도 링크가 됩니다. 글자가 주소 그대로인 링크가 40칸을 넘으면 `https://` 를 떼고, 그래도 길면 가운데를 `…` 로 줄여 한 줄에 그립니다. 그래야 링크 전체가 눌리고, 누르면 전체 주소로 갑니다. OSC 8 하이퍼링크를 통과시키지 않는 멀티플렉서 안에서는 이름 뒤에 URL 이 흐리게 붙습니다.

## 개발

```bash
cd desk-look
claude plugin validate .   # 매니페스트와 훅 모듈 검사
claude plugin test .       # tests/*.test.tsx 실행
```

로컬 폴더를 그대로 마켓플레이스로 붙이면 저장소를 고치고 `/reload-plugins` 만 하면 됩니다.

```bash
claude plugin marketplace add ~/dev/git-repo/cc-desktop-mod
```

`.claude/skills/desk-release-check` 는 지난 점검 이후의 Claude Code 릴리즈 노트와 플러그인 API diff 를 모아, desk-look 이 쓰거나 걷어낼 거리를 찾습니다. 저장소 관례(최신 Claude Code 만 지원, 버전마다 GitHub 릴리즈)는 `CLAUDE.md` 에 있습니다.

`desk-asana`·`desk-slack` 에서도 같은 명령을 씁니다. desk-asana 는 댓글을 desk-look 의 마크다운 렌더러로 그리는데, 플러그인은 자기 폴더만 설치되므로 `desk-asana/hooks/shared/` 에 복사해 둡니다. `desk-look/hooks/markdown.tsx`·`diagram.ts` 를 고쳤으면 `scripts/sync-shared.sh` 를 돌려 함께 커밋합니다. 복사본이 어긋나면 릴리즈 워크플로가 실패합니다(`scripts/sync-shared.sh --check`).

`desk-look/.claude-plugin/types/` 는 엔진이 mod 를 로드할 때마다 다시 까는 타입 정의라 커밋하지 않습니다.
